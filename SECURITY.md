# Security Policy

## Supported versions

Security fixes are applied to the latest published minor version.

## Reporting a vulnerability

Do not open a public issue for a vulnerability. Use GitHub private vulnerability reporting for this repository. Include a minimal reproduction, affected versions, expected behavior, actual behavior, and whether the issue requires authentication or a specific non-default configuration.

Please do not include real production secrets, tokens, personal data, customer data, or exploit traffic against systems you do not own.

## Scope

Reports are especially welcome for:

- Authentication or verification bypasses
- Prototype pollution or parser differentials
- CRLF injection
- Open redirects or CORS policy confusion
- SSRF policy bypasses
- Archive extraction escapes
- Secret leakage in logs or error responses

## Response goals

Reports are triaged as quickly as possible. If a report is valid, a fix, regression test, and advisory are prepared before public disclosure where practical.
